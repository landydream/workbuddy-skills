# Cocos + FairyGUI 游戏模块开发

做法来自一个 Cocos Creator 3.8.8 + FairyGUI 正式工程（框架层 framework/ / 平台层 platform/ / 业务层 game/（core 公共 + module 各系统）/ vendor 库不改，依赖单向：业务 → 框架）。

## 1. 模块包自洽、零互引

一个业务系统一个目录，**拷走整个目录就是完整的一个模块**：

```
module/hero/
├── README.md        模块自述：协议/界面/事件/占用的全局定点/每个文件一句话/坑
├── Model_Hero.ts    模块本体：构造函数 registerView 声明界面，onRegister 收协议；
│                    模块自己的常量、MSG_ 消息、界面 id、红点 key 都收在这个文件里
├── HeroRes.ts       资源路径与资源组（需要时才建）
└── ui/              界面（View_XX / Page_XX / Item_XX）
```

- 自述跟代码走：改代码和改自述在**同一个 diff**，文档不掉队。
- **模块之间不 import**：跨模块调用走 `getModel<调用面>('name')`（名字字面量必须等于对方 NAME，有校验盯着拼错），类型用公共调用面接口；没有调用面就只声明自己用到的那几个成员。跨模块通知走全局事件。
- **不为单个模块改框架**。框架不认识任何具体模块，反向 import 禁止。
- 模块自己的参数/资源/事件收在模块目录里，不散进全局配置——参数散在全局，拷走就少一半。

## 2. 五个全局插入定点

模块接入**允许插入的全局文件只有五个**，全在 module/ 目录根下：

| 文件 | 放什么 |
|---|---|
| `GameModules.ts` | 模块注册表，加/删模块改一行（`App.modules.add(new Model_X())`） |
| `Enum_Space.ts` | 协议字段号（**全项目一个 enum**） |
| `GameEvent.ts` | **跨模块**事件名（模块自己的 MSG_ 收在自己 Model 里） |
| `ReddotKey.ts` | **跨模块**红点 key |
| `UIConst.ts` | 全局界面 id 表（模块界面 id 进自己的模块段） |

**多人协同技巧**：插入行按模块名字母序放固定位置、各模块用自己的号段——SVN/Git 行级合并时不同模块改不相邻的行基本不冲突。

## 3. 编号纪律：用过不改不复用

- 字段号、UI id、坑编号：**数字写死、无运算**；和服务端两边同步改；**用过不改不复用**。
- 新增 id 前在整个 enum 里搜一遍这个数字，全局没人用过才能用；存量的历史撞号当基线机械校验（撞号数超基线就红），要动存量连校验基线一起改。
- 撞号导致 `enum[数字]` 反查不可靠，判段归属用 key 前缀集合。

## 4. 公共层升级判据

`core/common/`（跨模块调用面、公共 UI 件）随模块需要变，规矩三条：

1. **第三个模块要用时才升公共**——前两次各自留在自己模块里（防过早抽象）。
2. 改前先拉最新版本，**只加不改既有签名**。
3. 升了公共的东西在报告里点名，让负责人知道。

模块自己的 FGUI 扩展组件不经全局装配，`BaseModel.setExtension` 就地注册。

## 5. 协议迁移纪律

- 旧协议是兼容边界：**协议名、协议号、字段类型、读取顺序不改**，发包保持 `write().byte(x).int(y).send(cmd)` 连续调用（缓冲复用，write 到 send 之间不许断）。
- 命名对齐协议工具生成：`CGxxx` 发 / `GCxxx` 收，**生成的名字不许改**，协议号直接写数字。
- **协议网站导出的代码是骨架，照抄就是坏代码**（实测：循环变量名错、类型循环体为空、缺 export、继承旧基类）——只取协议号/方向/字段串，代码按本工程写法自己写。
- **写成常量的协议号扫描工具抓不到**（如心跳由网络层直接收发）：加同类常量要手工核号。
- **在用但协议网站查无定义的号是定时炸弹**：服务端随时可能把这些号分给别的系统。接对应系统前先全局查重申请，别默认它归我们。新增号同理：先全局查重（查得到 = 已被占）。
- 有专门的协议核对工具时：拿协议工具导出的前端 TS 当权威，报四类差异（查无此号/两模块撞号/方向相反/服务端已备好但我们没实现）。

## 6. 与服务端的运行时契约（不能破坏的约定）

1. **Ready 才能发业务协议**：首登和重登都要角色数据包到手才 markReady。
2. **回包必须过防重闸门**：模块层 pending 代次 + 步骤层 acceptResponse(seq)。
3. **流程步骤必须可重入**：断线恢复会重新 onEnter、请求重发。
4. **账号只存登录参数，没有就明确失败**，不退默认账号——不可恢复的错误当场失败报错，不许伪造默认值让流程看起来正常。
5. **和服务端无关的活儿做成并行任务**，不做成串行启动步骤。

## 7. FGUI 相关

- **扩展组件必须早于组件实例化注册**：因此公共格子能力的模块安装顺序必须排在所有用它的业务模块之前（装配表里依赖方排在使用方之后）。
- **界面包/图声明不全不报错，现象是面板空白**：跨包依赖没进 preLoadPackages、大图没 preLoadRes 进组，只会留白。验收标准：首开不见半成品，重开不闪加载页。
- 包名是编辑器定的，和文件名不一致时用包路径登记表映射。
- 图片地址集中一个工具类生成（散图 `images/...`、包内 `ui://包名/资源名`），不许各模块自行拼多套规则。

## 8. 会话重建与 static 生命周期

- 切区/切账号/注销走**整包重建**（App 拆掉重启、模块实例全换新），不做字段清洗。
- **模块外的 static（单例 `ins`、对象池 `POOL`）必须在模块 onDestroy 里亲手拆**——模块实例换了，static 活着，不拆的话下一局摸到的是上一局的残留。
- 界面只画状态，不做全局策略（如重连遮罩何时出现归 UI 管理器的策略位）。

## 9. 验证

- 类型检查用命令行 tsc，**别拿编辑器代跑**（编辑器开着时会静默假零错）。
- 框架纯逻辑改动：单测前后各跑一遍；新用例 = 一个测试文件 + 入口注册一行。
- 每日收工跑一键门禁（单测 + 文档校验 + 整洁检查），自己改的文件里的红必须清掉。

## 10. 引擎级高频坑（血泪清单）

| 坑 | 修法 |
|---|---|
| `useDefineForClassFields`/`allowDeclareFields` 开了任一个，FairyGUI 输入组件内部字段被抹成 undefined 报错 | 两个都关（settings/v2/packages/project.json），改完重启编辑器；父类构造里虚方法赋值的字段，子类别写 `= null` 初始化器 |
| 裸 `new Node()` 默认 DEFAULT 层，UI 相机不画它——**整棵子树不渲染不报错** | UI 节点走统一创建入口设 layer |
| 从旧引擎（2.x）工程拷美术带了 .meta，3.8 不认 | 拷资源剥 .meta；清坏 meta 先关编辑器 |
| 配置表数据在进场屏障之后才保证就绪 | 更早取是 undefined，把取数挪到屏障后 |
| 位图字体按固定字符清单烘的 | 塞清单外字符先查 .fnt 缺字，缺字直接崩渲染帧 |
| 区服 id 不是全局唯一（每个大区从 1 编号） | 拿它当全局键会互相覆盖；挂在大区对象下做键 |
| 场景里入口组件的 uuid 与脚本 .meta 绑定 | 别手工改 |
