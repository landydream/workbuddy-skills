# 多人多 AI 会话的仓库治理

所有做法来自一个正式游戏工程（Cocos Creator 3.8.8 + SVN 多人协同 + 多 AI 并行）的实战沉淀，可整体移植到任何长期演进的仓库。

## 1. 核心原则：知识只住在中立层

用什么 AI 会变，规矩不能跟着变：

- 知识只放在**与 AI 品牌无关**的中立层（共读文档 + 模块自述 + 工具脚本）。
- 每家 AI 的配置文件**只许写一句"去读哪一份"**，不写任何正文。
- **验收标准：删掉任意一家的配置文件，工程的规矩一条都不少。** 谁把约定的正文、清单、表格搬进自家配置，就是制造第二份——改一处忘一处，分叉比缺失更难查。
- 接入新 AI 两步：①建入口文件，内容照抄那句指路话（**别用 symlink**——Windows 要管理员权限，SVN 检出会变成文本文件）；②在登记表和 doc-check 里显式注册一行，让校验盯着它保持零知识（行数上限 + 必须指回中立层）。

## 2. 文档分三层，各管一件事

| 层 | 放什么 | 特征 |
|---|---|---|
| **宪法** | 十来条几乎不变的硬规矩（代码风格、边界、做完的标准、何时必须停下来问） | 页数恒定，改走提案流 |
| **路由/地图** | ①按任务的阅读集（"做 X 读哪几份、动哪里"）②代码里看不出来的事（外部契约、不能破坏的约定、编号坑列表） | 只收这两类知识 |
| **模块自述** | 每个模块目录一份 `README.md`（协议/界面/事件/每个文件一句话/坑） | 跟代码同住一个目录 |

三条文档纪律（防腐烂的根）：

1. **文档只放知识，不放进度。** 进度写两处：框架/平台的写成代码里的 `TODO` 注释（就写在那个函数上方）、模块的写在自己 README 的进度段；都在改完的同一个 diff 里删掉——不会出现"文档说没做、其实早修了"。
2. **能从代码推导的不写文档**（目录结构、调用链）。文档跟着代码腐化，文件头注释永远更准。同理**文档里不留模块清单**——"有哪些模块"只看模块注册表源文件，代码跑得起来它就是准的。
3. **阅读集与工程总规模无关。** 一个模块会话的固定阅读集 = 宪法 + 路由 + API 导览 + 自己模块目录（含 README），约 600 行封顶——再加一百个模块这个数字也不变，因为别人的模块自述在别人的目录里。

## 3. 共读文档的修改：待合并提案流

多人多 AI 并行改同一份共读文档，语义冲突没法靠行级合并解决。解法：

- **直接改**：只有模块自己的 `README.md`——一份文件一个主人，天然不撞车。
- **走待合并**：其余一切共读文档。不动原文件，往 `docs/协作/待合并/` 放一份提案：写清**改哪份哪一节 / 原文（贴够定位的一小段）→ 改成什么 / 为什么**，命名 `<日期>-<改哪份>-<一句话>.md`。负责人（或其指派的 AI）统一合并，**合并后删掉提案文件**，目录空着是常态。
- 效果：共读文档在版本库里永远是"一个人在改"。

## 4. 机械门禁：能自动查的就不靠自觉

两道静态门禁随一键测试跑，**都跑完不短路**，退出码取二者之或：

| 门禁 | 查什么（可机械判定的） |
|---|---|
| doc-check | 共读文档出现本机绝对路径（红灯）、协议字段号撞号超基线、AI 入口文件零知识（行数上限 + 必须指回宪法） |
| clean-check | 注册型回调禁匿名函数、catch 不许空、单方法长度 |

配套纪律：**门禁是提醒——你改的文件里的红必须清掉，别人的存量红不算你的**；提示项（软指标）只看趋势。机械查不了的部分写进宪法让 AI 会话开头就在手上（如"每个函数能不能用一句不含'和'的话说清""失败路径写了吗"）。

**危险命令闸门**：执行前拦不可逆操作（`svn revert -R`、`git clean -x`、删版本库元数据、`rm -rf /`、强推等）。脚本进版本库、注册行不进（各人在自己机器挂一次）。

## 5. 做完的标准（全过才算完）

1. 类型检查零错（只算自己改的文件）
2. 门禁无新红（单测 + doc-check + clean-check）
3. 改了框架纯逻辑就补单测；**抓到过 bug 的用例是回归，不许删**
4. 自己模块的 README 在**同一个 diff** 里改掉
5. 报告里给出改了什么和验证结果——**不用"应该没问题"代替证据**

## 6. 决策日志怎么记

按日期倒序记**当天已经发生的**改动、踩坑、可复用片段，两条铁律：

- 未核验的推测不写成事实；只记录当前工作区状态，不把所有未提交变更归因于单一会话。
- 大仓库的 `git/svn diff` 不等于"今天的改动"（实测一个工作区 867 项未提交状态，混着历史内容）。用**文件修改时间 + 模块自述 + 会话记录交叉核验**。

## 7. 机器差异的处理

- 共享文档里**禁止本机绝对路径**（个人目录、各自的源码工程位置）——用门禁红灯强制。
- 机器差异走**环境变量**（工具认 `XX_NODE` 这类变量，共享文件里不写任何人的路径）或**各自的 AI 记忆**。
- 厂商默认安装目录这种全员一致的路径可以写。
- `*.local.*` 结尾的个人配置不进版本库。
- 为老模型短板写的规矩要定期复检（3~6 个月或换 AI 之后）：新模型上会变成纯负担，该删就删。
